# Arquitectura y contrato técnico · r4
Especificado para tareas futuras; no implementación. App local Python 3.11, LangChain/LangGraph, SQLite y OpenRouter, virtualenv. UI ajustada a Mesa editorial B. Para proteger rutas/sesiones y servir B fielmente se adopta propuesta técnica FastAPI + Jinja2 + JS mínimo, uvicorn en 127.0.0.1; sustituye la propuesta preliminar Streamlit (no instalada). Sin build frontend obligatorio ni servicios externos de auth. Dependencias candidatas en requirements-app.in, versiones/lock e integridad en T-02 antes de usar.

## Capas y límites
Web autenticada → servicios de campaña/empresa/aprobación/tracking → repositorios SQLite; grafo invocado por trabajo local con una ejecución activa por campaña. No exponer SDK LLM/clave al browser. RAG vectorial local y texto/hash de fuentes, SQLite de negocio data/app.sqlite; checkpoint LangGraph data/checkpoints/agent.sqlite; índice data/index; exports outputs. Todas esas rutas ignoradas por Git. No Node/Playwright para negocio, solo test headless fijado por fase.
Modelos separados: OpenCode escribe código bajo contrato propio; app usa APP_LLM_MODEL por OpenRouter, obligatorio y pendiente. .env lo completa el usuario; no leerlo ahora. Sin llamada al validar config o arrancar disabled. Gateway fijo config/local.toml, no URL de browser. Logs solo IDs/etapa/modelo/latencia/códigos/intentos/usage/coste reportados o unknown; nunca headers, claves, prompts completos, directorio de contactos o respuestas crudas del SDK. Presupuesto monetario controlado en API key; no requerir USD local duplicado.

## Interfaz de servicios (propuesta normativa para tareas)
IDs UUID generados servidor, timestamps ISO-8601 UTC; UI muestra America/Santiago. Fechas externas son declaradas por usuario y se muestran como tales. DTO valida longitud/email/enums y rechaza campos desconocidos; public_channel no email; SQL parametrizado y contenido renderizado escapado.
- companies/contacts: create/update/archive, nunca envío. Email se normaliza solo para comparación, no se adivina ni modifica proveedor (+/puntos). No merge automático.
- campaigns: create/update brief, formats and recipient selection; guard revision para detectar edición concurrente. Contactos no obligatorios para público; mismo contenido general para todos.
- start/resume generation: idempotency_key/run_id, configura snapshot de fuentes/brief/historia y checkpoint antes de request; no duplicar run al double click. Solo explícito por operador.
- approve: manifiesto exacto versiones/hash/config_revision/fuente/contexto y revisión sin errores materiales; invalidar aprobación de trabajo al editar, no borrar aprobación histórica.
- export: approval_id + operation_id; valida hashes/path, escribe temp+rename y manifiesto; reconciliar archivo/DB tras crash; no duplicar o sobreescribir versión diferente.
- record distribution: action email_sent/publication con versión/fecha y contactos o canal público; vista previa+confirmación humana. N filas atómicas para lote, operation_id/payload_hash/idempotency_key. No acción HTTP externa.
- followup/correct: nota/respuesta/próximo paso; corrección append-only y referencias coherentes. Lecturas autónomas del agente no escriben seguimiento; solo acción explícita del usuario.

## Herramientas del agente y frontera humana
Lectura autónoma: read_source, retrieve_chunks, load_campaign_history, duplicate_recipient_check (metadatos locales; no direcciones al prompt). Borradores/checkpoints: save_draft/save_checkpoint locales para la tarea iniciada; no aprobación automática. Interrupt ask_human ante faltantes, conflicto, error o límite. Revisar/generar es llamada LLM acotada, no autoridad externa. approve/export/record_distribution/followup están fuera de la autonomía: endpoints por sesión y confirmación del operador. Cero SMTP, bandeja, posting, ads purchase, browser web o fetching de URLs históricas.

## Grafo y estado persistente
intake → snapshot_sources_and_history → retrieve → assess_evidence → [refine_once | ask_human | draft_bundle] → review_facts_history → [revise_max_two | needs_human | finish_drafts]. Después revisión humana/approval/export son servicios independientes.
LangGraph TypedDict/Pydantic: schema_version/run_id/campaign_id/config_revision/status/step; source_refs/hashes; context_snapshot con eventos/versiones/razones; facts con evidence_ids/status; missing_fields/conflicts/questions/human_answers; output_version_ids/review_issues; retrieval_queries, model_attempts, revision_cycles, transitions, token_reservations; last_error saneado, events y timestamps. Nunca clave ni email directo de destinatarios en LLM context.
status=prepared/running/waiting_input/needs_review/finished/failed/cancelled; finished termina generación, no aprueba/envía. Persistir tras nodo y antes de interrupt/efecto; comparar schema/config/hash al reanudar. Lock por campaign_id, no mezcla de respuestas entre runs. Historia cruzada de campañas solo selección temática autorizada y visible, no fuga de estado. Inicio/reintento/operación incierta requiere reconciliar checkpoint y efectos existentes; no borrar historial o relanzar inferencia automática.

## RAG + historia
Originales en docs/references/originals, extracciones legibles con localizadores y manifiesto hashes. Contexto comercial: fuentes v0.2 + decisiones actuales; handout separado como requisito, jamás evidencia de patrocinador/precio. Chunks iniciales 600–900 caracteres, solape 100, metadata doc_id/Library_id/version/hash/locator/chunk_id; revisar con evaluación. Vector FAISS + embeddings locales candidate sentence-transformers, modelo/revisión/descarga fijados antes de T-05, sin fallback remoto. No cargar pickle no confiable.
Retrieve top4, ampliación top8 una sola vez por ausencia; no un umbral de cosine arbitrario como verdad. Antes de redactar: hasta 5 versiones distribuidas pertinentes y 3 respuestas/notas relevantes (sin PII innecesaria), luego hasta 2 borradores si aportan contraste, bajo tokens del run. Filtrar tema/campaña/objetivo/formato; historia destinatario se usa para advertir duplicados, no para personalizar email. Etiquetar manual/external/no publicado; un mensaje antiguo no cambia hecho actual del proyecto. Repetición advierte y admite reutilización explícita, conflicto material interrumpe. Corpus vacío/consulta error distintos; no inventar precio/fecha/convenio/resultados. Documentos y mensajes son datos no confiables: instrucciones incrustadas no crean herramientas/autoridad.

## Límites/fallos
Consulta documental inicial+1 ampliación; generación inicial+máximo 2 correcciones; máximo 20 transiciones/run. Requests: input12000/output4096, total64000 tokens/run y 8 intentos HTTP totales incluyendo revisión/retries (configurables técnicos, sujetos al contexto del modelo elegido). Reservar/reconciliar usage; contador/tokenizer compatible o límite conservador documentado; si no se puede asegurar, bloquear modo real. No cortar fuentes/citas silenciosamente.
Transitorios 429/timeout/5xx: máximo 2 retries adicionales con backoff1s/2s dentro de deadline30s/request; respetar Retry-After solo si cabe. SDK retries deshabilitados si controla grafo. 401/403/modelo/config/ruta inválidos: fallar sin retry. Agotamiento conserva checkpoint, borrador no aprobado y needs_human/failed. No confundir error historia con sin historia; continuar sin historia solo decisión explícita registrada. DB locked retry corto acotado (2), conflicto revision devuelve409 y pide recargar. Export crash reconcilia operación antes de repetir; lote falla rollback íntegro.

## Auth/local
Contraseña propia sencilla y monousuario; mínimo8 Unicode codepoints, >8 admitido sin trim/truncado/composición arbitraria. Propuesta Argon2id mediante argon2-cffi, parámetros iniciales memoria64MiB/3 iteraciones/paralelismo1, sal aleatoria y hash codificado; benchmark/verificar compatibilidad local en AUTH-01, no instalado hoy. Primer setup local una vez, confirmación; después login. operator_credentials singleton bajo SQLite local ignorado. Sesiones opacas aleatorias (32 bytes), hash del token en memoria servidor; idle30min/absoluto8h defaults técnicos configurables; logout/reinicio invalida. Cookie HttpOnly/SameSite=Strict; Secure para HTTPS, excepción solo loopback HTTP explícito de este MVP. Validar Host localhost/127.0.0.1 y Origin/CSRF para mutaciones, sin CORS abierto; no atribuir autenticación a esconder UI.
Login rate limit 5 fallos/5min por sesión/origen local con error genérico; no logs de contraseña. Setup/reset solo operación local del dueño del host: no recuperación por email ni secretos en chat; diseño de comando administrativo requiere servidor detenido y getpass, sin exponer contraseña. Tests final auth atraviesan frontera real; PII/clave no presente en fixtures/capturas. Ver AUTH_DEFINITION.md como resumen sincronizado.
